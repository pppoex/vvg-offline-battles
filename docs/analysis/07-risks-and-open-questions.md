# 07 - 风险与开放问题

> 分析时间：2026-09-12
> 说明：记录项目风险、未知项、需要用户确认的问题

## 1. 风险评估

### 1.1 高风险

#### 风险 1: x64 native 实例守卫重写

- **描述**：0.9.22 的 32-bit native 实例守卫无法直接用于 2.3.1.2（64-bit x64）
- **影响**：多实例限制无法解除，联机测试无法进行
- **概率**：高（确定需要重写）
- **缓解措施**：
  1. 专门的逆向分析任务
  2. 使用 Process Explorer / Process Monitor 观察运行时行为
  3. 使用 PE 分析工具提取 RVA
  4. 参考 0.9.22 的实现思路，适配 x64
- **备选方案**：
  1. DLL 注入 Hook CreateMutexW/OpenMutexW
  2. 独立用户会话 / 沙箱
  3. 虚拟机
- **状态**：**待解决**

#### 风险 2: 2.3.1.2 WGC 结构未知

- **描述**：2.3.1.2 的 Wargaming Game Center 结构未逆向，不知道互斥体名和 cleanup thunk RVA
- **影响**：无法实现 native 实例守卫
- **概率**：高（需要逆向）
- **缓解措施**：
  1. 运行时探测互斥体名
  2. 反编译 wgc_api.dll
  3. 参考 0.9.22 的 WGC 结构
- **状态**：**待解决**

#### 风险 3: BigWorld API 变化

- **描述**：2.3.1.2 的 BigWorld API 可能与 0.9.22 有重大变化
- **影响**：参考项目的客户端代码无法直接使用
- **概率**：中（从 Offline2.3.1.2 代码推断有变化）
- **缓解措施**：
  1. 从 Offline2.3.1.2 提取 API 用法
  2. 逐步验证 API 兼容性
  3. 必要时重写客户端代码
- **状态**：**部分已知**

### 1.2 中风险

#### 风险 4: 机制系统复杂度

- **描述**：2.3.1.2 引入了复杂的载具机制系统（mechanics.py 243 KB）
- **影响**：战斗逻辑迁移工作量大
- **概率**：中
- **缓解措施**：
  1. 分模块迁移
  2. 逐步验证
  3. 优先实现核心机制
- **状态**：**已知**

#### 风险 5: Python 2.7 限制

- **描述**：客户端必须使用 Python 2.7，无法使用现代 Python 特性
- **影响**：客户端代码开发受限
- **概率**：确定
- **缓解措施**：
  1. 客户端只用标准库
  2. 服务器用 Python 3
  3. 协议层用 JSON（标准库支持）
- **状态**：**已知**

#### 风险 6: pyc magic number 兼容性

- **描述**：2.3.1.2 的 Python .pyc magic number 可能与 0.9.22 不同
- **影响**：部署的 mod 可能无法加载
- **概率**：低（都是 Python 2.7）
- **缓解措施**：
  1. 用目标客户端的 Python 编译
  2. 验证 .pyc 加载
- **状态**：**待验证**

#### 风险 7: 网络性能

- **描述**：JSON 序列化可能有性能问题
- **影响**：高频率消息可能影响性能
- **概率**：低（LAN 环境）
- **缓解措施**：
  1. 性能测试
  2. 必要时改用 MessagePack
  3. 优化消息大小
- **状态**：**已知**

### 1.3 低风险

## 2. 开放问题

### 2.1 需要用户确认的问题

#### 问题 1: 多实例方案选择

- **为什么需要确认**：多实例解除有多种方案，各有优缺点
- **可选方案**：
  1. **native C x64 + 引擎 WGC cleanup thunk**（推荐）
     - 优点：参考项目已验证类似方案
     - 缺点：需要逆向 2.3.1.2 的 WGC 结构
  2. **DLL 注入 Hook CreateMutexW/OpenMutexW**
     - 优点：不依赖 WGC 结构
     - 缺点：需要 DLL 注入，更复杂
  3. **独立用户会话 / 沙箱**
     - 优点：不需要修改游戏
     - 缺点：部署复杂，用户体验差
  4. **虚拟机**
     - 优点：完全隔离
     - 缺点：性能差，部署复杂
- **当前假设**：方案 1（native C x64 + 引擎 WGC cleanup thunk）
- **是否阻塞**：**是**（进入编码阶段前必须解决）

#### 问题 2: 客户端部署方式

- **为什么需要确认**：部署方式影响 mod 加载和更新
- **可选方案**：
  1. **res_mods 散装脚本**（推荐）
     - 优点：简单，易于调试
     - 缺点：文件较多
  2. **wotmod 打包**
     - 优点：文件少，易于分发
     - 缺点：调试不便
- **当前假设**：方案 1（res_mods 散装脚本）
- **是否阻塞**：否

#### 问题 3: Bot AI 范围

- **为什么需要确认**：Bot AI 复杂度影响工作量
- **可选方案**：
  1. **基础 Bot**（推荐）
     - 简单的移动、射击、目标选择
     - 从 Offline2.3.1.2 的 bots.py 简化
  2. **完整 Bot**
     - 完整的 AI 行为（导航、战术、弹药选择）
     - 从参考项目移植
- **当前假设**：方案 1（基础 Bot），后续迭代完善
- **是否阻塞**：否

#### 问题 4: 单人模式处理

- **为什么需要确认**：用户要求"不保留单机模式"，但单人也需要能玩
- **可选方案**：
  1. **单人也启动 sim-worker**（推荐）
     - 优点：架构统一
     - 缺点：需要启动额外进程
  2. **单人使用内置 sim-worker**
     - 优点：用户体验好
     - 缺点：架构复杂
- **当前假设**：方案 1（单人也启动 sim-worker）
- **是否阻塞**：否
